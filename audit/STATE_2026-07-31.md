**Plan C — measurement.** See §3.

**Plan C item C2 — the inline bash checks now have positive controls.** `selftest_validator.sh`
gains a sixth sub-test holding one planted defect per inline check (3, 5, 7, 8, 9, 10, 11, 12).
Each case asserts three things, and the first is what makes it a control rather than a
coincidence: the check's message is **absent** from the clean run, **present** in the planted
run, and the exit code / verdict / counter move as that check's severity implies (Checks 3, 5,
8, 10, 12 are error-level and must produce `verdict=FAIL`; 7, 9, 11 are warning-level and must
leave `errors=0` while the warning counter rises).

**Proven load-bearing, not merely passing.** Eight passing assertions prove nothing on their
own, so each was mutation-tested: neuter one check's reporting line and exactly that case flips
to a failure, with the other seven unaffected — a clean 8×8 diagonal, plus an unmutated control
in the same temp layout that passes all eight. Without that step the suite would be
indistinguishable from eight assertions that happen to match some other line of output.

> **One real finding, from the build itself.** The first version spelled the legacy agent-doc
> filename literally in the harness, so Check 7 — which scans this repo's own `*.md` **and**
> `*.sh` — flagged the harness. The gate's headline did not move (`warnings=5 errors=0 PASS`
> either way); only the count of files inside that one warning went 7 → 8. It was caught by
> reading the check's detail lines, not the verdict. The fix is to assemble the filename at
> run time, never to allowlist the file: suppression would hide future real instances there.
> This is the general hazard for any test or doc that describes a content-matching check.

## 4. Check registry — honest status

Rather than a fabricated "lifetime yield" column (a number with no artifact — the very
failure this session documented), each check carries what is actually known:

- **ANSWERED — has a registered synthesized positive control**, sentinel-enforced in
  `scripts/selftest_validator.sh`: Checks 14–22, 24, 25, 27–42. This answers *"can it
  catch its class?"*, which is the decision-relevant question.
- **RETIRED — inert tombstones**: Checks 4, 23, 26. All three retired 2026-06-07 at
  **zero lifetime catches**. Sized for removal this session — see
  `audit/stable_check_ids_sizing_2026-07-31.md`; recommendation is **do not renumber**.
- **ANSWERED — planted-defect control in `selftest_validator.sh` sub-test 6**: inline bash
  Checks 3, 5, 7, 8, 9, 10, 11, 12. This was Plan C item C2; **done 2026-07-31** (see §6).
  Checks 1, 2, 6 are still excluded as slated for removal.

- **STILL OPEN — no positive control**: inline Checks 1, 2, 6. These are *not* covered, and
  the gate does still run them; they were excluded from C2 only because R7 slates them for
  removal and writing controls for code you plan to delete is waste. If that removal does not
  happen, they are the remaining gap.

The two answered categories differ in kind and the distinction is worth keeping: an extracted
checker proves itself against a synthesized fixture inside its own process, whereas an inline
check is proven end-to-end through the real validator on a real fixture tree.

*"Did it ever catch a real bug"* is deliberately **not** tracked. Check 31 shipped at
"corpus 0 findings (preventive)" by design; zero lifetime catches is a valid outcome for
regression armour, so that metric would punish the right behaviour.

## 7. Standing hazard for whoever continues

Every error this session's reviews caught in my own work had one shape: **a confident
summary written without executing the thing that would settle it.** A fabricated
`module.gms:11,12` citation; a docstring asserting where four scalars live; a commit
metric that was not reproducible; "exactly one change" asserted three times without
diffing to the end of the file; a probe reporting all-zeros because it silently skipped a
string field; a rate quoted against the wrong base.

Every one was caught by *running something* — a checker, a diff, an independent agent.
None would have been caught by re-reading.
