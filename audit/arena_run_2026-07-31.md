## On the control files: the run's actual yield

Three findings landed on files with no injection. Under this tool's rules those are not
scored as false positives — the corpus is not certified clean — they are triaged. Triaged
here, by hand, against the live GAMS source:

**1. REAL, and invisible to the gate.** `cross_module/water_balance_conservation.md:71`
presents this inside a GAMS-fenced block, with a line citation:

    vm_watdem.fx(watdem_ineldo,j) = f42_watdem_ineldo(t,j,ssp_scenario,watdem_ineldo,"withdrawal");

`ssp_scenario` exists nowhere in `modules/`, `core/` or `config/`. The real code
(`42_water_demand/all_sectors_aug13/presolve.gms:39-52`) hardcodes `"ssp1"/"ssp2"/"ssp3"`
in an `if/elseif` on `s42_watdem_nonagr_scenario`, with a pre-`sm_fix_SSP2` branch forcing
`"ssp2"`. So a fabricated symbol is presented as a code quote.

`check_fenced_identifiers` reports **0 phantoms across 46 docs** and cannot see it.
`FENCED_IDENT_RE` matches only tokens carrying a MAgPIE type/module prefix (`vm_`, `pm_`,
`sm_`, `[vpfisc]\d+_`). `ssp_scenario` has neither, so it is never treated as an identifier
and never existence-checked. **The checker's coverage is inversely correlated with
fabrication risk** — an invented placeholder reaches for a readable name, not a
convention-conforming one. That is the actionable defect this run found.

The string also appears at `audit/archive/rounds/round48_answers/P4_answer.md:54`, so it is
not a recorded finding: it passed through a semantic audit round unchallenged and
propagated into the doc.

**2. REAL.** `cross_module/water_balance_conservation.md:101` cites
`42_water_demand/all_sectors_aug13/input.gms:35-36` for a three-bullet EFP block. Those
lines carry only `s42_efp_startyear` (2025) and `s42_efp_targetyear` (2040), which support
the first bullet; `EFP_countries(iso)` is at `:52`. And `$setglobal c42_env_flow_policy off`
at `:122` means the policy is **off by default** — the doc describes the ramp and the
targeting without saying they are inactive as shipped. Capability-vs-default, which is one
of the 22 MANDATEs. (Verified: the citation scope and the default. The agent's fuller
`p42_efp` -> `i42_env_flow_policy` trace was not re-derived.)

**3. FALSE — and this is the most informative result in the run.**
`modules/module_41.md:619` says the default croparea realization lists `vm_AEI` in its
`not_used.txt`. The agent called this fabricated, asserting *"No file named not_used.txt
exists anywhere in the MAgPIE modules/ tree"* and citing having run `find -iname
'*not_used*'` across the whole tree for "zero results."

`../modules/30_croparea/simple_apr24/not_used.txt` exists. Line 2 is
`vm_AEI,input,questionnaire`. The doc is correct.

The agent reported running the exact command that would have refuted it, and reported the
opposite outcome. The finding came with severity Major, a stated method, and a cited
directory listing — every surface of a well-evidenced claim. **It was caught only because
the result carried a verify-before-acting flag and the verification was actually
performed.** Nothing in the finding's own presentation distinguished it from the two true
ones.

## What this run supports

- LLM auditors **do** find real corpus defects the deterministic gate cannot see: two
  confirmed, both of classes the gate has no checker for.
- They **also** produce confident, method-citing false positives at a comparable rate: 2
  true, 1 false out of 3 triaged.
- So an LLM audit arm is a **lead generator, not a verdict source**. Its output needs the
  same independent re-derivation this project already requires for model-bug claims. That
  is a design constraint on any flywheel built from it, and it is measured here rather than
  assumed.

## What it does not support

- Any tier comparison. Four arms did not run.
- Any statement about whether the four blind classes are visible to a strong auditor. The
  only tier that completed found none of them, and also found none of anything else in the
  seeded files.
- Any aggregate detection rate. n = 4, one tier, two runs.
